// WHAT THE CLUSTER MODULE BUILDS

A cluster that can be destroyed and recreated freely, with everything durable kept outside it.

Cilium in ENI mode

No AWS VPC CNI, no kube-proxy. Pods hold routable VPC addresses, Cilium replaces kube-proxy, and it implements the Gateway API behind one NLB.

Karpenter capacity

Terraform owns the IAM, the interruption queue and the NodePool shape. The platform renders the NodePool. A small system node group carries the controllers.

Flux from the first apply

flux-operator, one FluxInstance and a platform entrypoint image. Flux then adopts every release Terraform bootstrapped, so upgrades ship by publishing, never by apply.

Signed end to end

Charts, images and manifests are cosign-signed, keyless by default or with KMS. They're verified by flux before they sync and by Kyverno at admission.

Pod Identity everywhere

Every workload with a pod gets a role through an EKS Pod Identity association. Podless secret syncs use IRSA, with deterministic role names published as one prefix.

Self-owning applications

Each application is its own signed image. Terraform seeds it once, and the image adopts its seed, so releasing an application never needs terraform apply.

// ONE CONTRACT WITH THE PLATFORM

Every fact the manifests need arrives in the cluster-vars ConfigMap.

kubectl -n flux-system get configmap cluster-vars
PLATFORM_COMPONENTS# the electable tier the entrypoint ranges over
FLUX_SYNC_URL# the entrypoint, so a running cluster can be re-pointed
PLATFORM_DOMAIN# the wildcard Gateway listener every route hangs off
SIGNED_IDENTITY_*# the cosign identities flux and Kyverno verify against
KARPENTER_*# the NodePool shape the platform renders
SECRETS_ROLE_PREFIX# one prefix for every IRSA secret-reader role

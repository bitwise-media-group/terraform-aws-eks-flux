# cluster (root)

The root module: an EKS cluster running Cilium in ENI mode and Karpenter, bootstrapped into flux-operator and syncing a
cosign-signed platform from ECR.

```hcl
module "cluster" {
  source = "git::https://github.com/bitwise-media-group/terraform-aws-eks-flux.git?ref=vX.Y.Z"

  name              = "platform-x"
  network           = { vpc_id = "vpc-…", node_subnet_ids = ["subnet-…", "subnet-…"] }
  platform_registry = module.cache.platform_registry
  signed_identity = {
    manifests_subject  = "…"
    containers_subject = "…"
  }
}
```

Only those four inputs are required. Everything else is an optional surface that stays off, or takes a sensible default,
until you configure it. [Examples](../getting-started/examples.md) has a minimal and a complete root.

## Input groups

The inputs fall into a few groups. The full table is below.

- **Required wiring:** `name`, `network`, `platform_registry`, `signed_identity`.
- **Control plane:** `kubernetes_version`, `upgrade_policy`, `public_access`, `cluster_log_types`,
  `encryption_kms_key_arn`, `cluster_admin_principals`, `rbac`.
- **Capacity:** `system_node_group`, `node_groups`, `karpenter`, `cilium`, `addons`.
- **Serving:** `dns`, `gateway`, `observability`.
- **Platform election:** `platform_components`, `sso`, `flux`, `secret_prefix`.
- **Application wiring:** `applications`, `application_vars`, `workload_grants`, `workload_identity.secret_readers`,
  `flux.namespaces`. See [Applications](../concepts/applications.md).

## Provider configuration

The module needs `aws` and `helm` providers configured by the caller. Configure helm's Kubernetes auth with an `exec`
plugin running `aws eks get-token`, plus ECR registry credentials for the chart pulls. See the
[examples](../getting-started/examples.md#complete) and
[Caveats](../reference/caveats.md#the-helm-provider-needs-the-aws-cli).
